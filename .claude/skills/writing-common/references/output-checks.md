# 출력 확인 기준

요청한 매체에 해당하는 항목만 적용한다. 다른 파일 형식을 새로 제작하라는 지침이 아니다.

## 저장·분량·링크

- 실제 반영 요청이면 최신 합의안이 지정 파일에 저장되었는지 읽어 확인한다. 문장 제안만 했으면 파일 반영으로 보고하지 않는다.
- 글자 수 상한과 정확한 글자 수 요구를 구분한다. 회사별 제한이면 각 본문을 따로 계산하고, 소제목·공백·줄바꿈·불렛 표기의 포함 범위를 밝힌다. 중간 초안이 아닌 최종 전달본을 센다.
- GitHub·블로그·포트폴리오 등 링크의 실제 주소와 대상을 확인한다. 주소 표기 확인과 접속·내용 확인은 구분하며, 열지 못한 링크는 접근 검증 완료로 보고하지 않는다.
- 폰트·본문 크기·제목 단계, 정렬·여백·줄바꿈, 표 잘림과 읽기 순서를 요청 매체에서 확인한다. 문서 내용 검토와 실제 레이아웃 검토를 구분한다.

## HTML·웹 콘텐츠

- 해당 화면을 실제로 확인할 수 있으면 제목·요약·상세·근거의 탐색 흐름, 링크·목차 이동, 확인한 화면 폭의 잘림과 읽기 순서를 점검한다.
- 읽는 순서·제목 단계·본문 대비·간격·글줄과 좁은 화면의 재배치를 확인한다. 대비는 WCAG AA(일반 텍스트 4.5:1, 큰 텍스트 3:1)를 기준으로 하되 실제로 측정했을 때만 수치로 보고한다. 320 CSS px 폭에서 정보·기능 손실 없이 재배치되는지 본다. 일부 화면 폭 확인만으로 WCAG 적합성을 인증하지 않는다.
- 데스크톱만 보았다면 모바일까지 검증했다고 하지 않는다. 콘텐츠 검토가 코드 변경·라우팅 재설계·배포 권한을 부여하지 않는다.
- 이력서의 사용자 한정 HTML 동작은 이력서 전문 스킬의 선호 참조에 따른다. 포트폴리오나 일반 사이트의 기본 동작으로 확대하지 않는다.

## PDF

- 최종 PDF를 실제로 열거나 렌더링하여 줄바꿈·페이지 나눔·과도한 간격·표 잘림·글꼴·링크를 확인한다. 작은 글씨로 억지로 페이지 수를 줄이지 않는다.
- HTML에서 PDF로 출력할 때 간격·페이지 나눔 조정이 필요하면 `전체 너비 조정 → HTML 내보내기 → 브라우저 인쇄 → 페이지 여백 조정`을 선택할 수 있다. 현재 도구와 요청 방식에 맞춘 방법이며 필수 절차는 아니다.
- Markdown이나 HTML만 작성했거나 최종 PDF를 보지 못했다면 PDF 분량·레이아웃 검증은 미완료로 알린다.
