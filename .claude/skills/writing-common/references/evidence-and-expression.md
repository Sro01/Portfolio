# 근거와 표현

문장을 쓰거나 주장의 범위를 정할 때 참고한다. 사실 판정 기준은 공통 스킬 본문을 따른다.

## 근거의 강도

- 이력서·포트폴리오 본문은 자기보고다. 사실 검증을 마쳤다는 뜻이 아니다.
- 코드·PR·문서는 구현과 판단의 추가 근거다. 테스트는 그 조건에서의 동작 근거이고, 운영 결과는 기간·대상·수집 방식이 있을 때 그 범위의 효과 근거다.
- 화면 관찰은 관찰 시점의 전달력 근거일 뿐 채용 결과나 실무 역량 전체를 증명하지 않는다.
- 수치가 없어도 확인 가능한 동작 변화, 회귀 검증, 채택·완료 같은 결과를 근거로 쓸 수 있다.

## 표현의 차이

아래는 가상 예시다. 오른쪽 표현은 해당 사실이 원자료에서 확인된 경우에만 쓴다.

| 피할 표현 | 확인된 사실로 가능한 표현 | 차이 |
|---|---|---|
| 백엔드 전반 개발, 기여도 80% | 팀 프로젝트에서 예약 API와 중복 예약 제어 담당 | 비율 대신 책임 경계 |
| Redis로 성능 대폭 향상 | 반복 조회 구간에 캐시를 적용하고 동일 부하 조건에서 응답 시간을 비교 | 조치와 검증 범위. 측정값이 없으면 향상을 확정하지 않음 |
| 장애를 완벽히 방지 | 중복 요청 테스트에서 같은 주문이 한 번만 생성되는 동작 확인 | 운영 무장애와 테스트 결과 구분 |
| 확장 가능한 클린 아키텍처 | 결제 제공자 호출을 어댑터로 분리해 공통 주문 흐름의 제공자 의존 제거 | 명칭 대신 실제 경계 |
| 협업 능력이 뛰어남 | 프런트엔드 담당자와 오류 응답 형식을 합의하고 API 문서에 예시 추가 | 자기평가 대신 행동 |
| 서비스 가입자 1만 명 달성 | 가입자 1만 명 규모의 팀 서비스에서 본인은 알림 재시도 흐름 구현 | 팀 규모와 개인 성과 구분 |
