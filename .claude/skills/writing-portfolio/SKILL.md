# writing-portfolio

독자가 프로젝트의 목적과 본인 책임을 이해하고, 실제 판단·변경·검증을 증거로 확인할 수 있는 포트폴리오 콘텐츠를 작성한다.

## 시작과 범위

1. [writing-common](../writing-common/SKILL.md)을 먼저 읽고 사실·기여·STAR 분석·문제 선별·차용 경계를 적용한다. 이번 작업에서 이미 읽었으면 중복 로딩하지 않는다.
2. 지원 직무·독자, 전체 구성/사례 상세/기존 내용 검토 중 요청 범위, 문서/PDF/웹 등 매체, 제공 자료와 연결할 이력서를 확인한다. 이미 주어진 정보는 다시 묻지 않는다.
3. 상세 사례를 작성하거나 증거 배치를 검토할 때 [사례 편집과 증거 설명](references/case-writing.md)을 읽는다. 전체 포트폴리오를 새로 만들거나 사이트 코드를 수정·배포하는 권한으로 확대하지 않는다.

## 사례 작성

- 직무와 관련 있고 본인의 책임·판단·실제 변경을 설명할 근거가 있는 경험을 고른다. 각 사례에서 독자가 확인할 핵심 주장을 정한다. 기능 수나 기술 수가 많은 순서로 고르지 않는다.
- 다음 요소를 자료에서 확인하여 연결한다. 빠진 근거를 찾는 분석 항목이며 모든 사례에 같은 소제목·분량을 강제하는 템플릿은 아니다.

| 요소 | 독자가 이해할 내용 |
|---|---|
| 목적·문제 | 누구를 위한 서비스인지, 해결하려는 문제나 달성할 목표 |
| 제약 | 당시의 규모·기존 구조·운영 조건·개발 제약 중 판단에 영향을 준 사실 |
| 책임 | 팀 전체 범위와 구분되는 본인의 역할·책임·직접 한 일 |
| 판단 | 무엇을 왜 선택했는지, 실제 검토 기록이 있는 대안과 선택 기준 |
| 실제 변경 | 바꾼 처리 흐름·구조·구현과 변경 전후의 구체적인 차이 |
| 검증 | 어떤 환경·방법으로 무엇을 확인했고 어떤 결과를 얻었는지 |
| 한계 | 확인하지 못한 환경·효과, 남은 제약과 현재 상태 |

- 결과와 핵심 변경을 먼저 이해할 수 있게 쓰고, 필요한 문제·제약·판단 근거를 이어 설명한다. 조사·시도·실패를 시간순으로 모두 늘어놓는 대신 최종 선택을 이해하는 데 필요한 경로를 남긴다.
- 대안 검토 기록이 없으면 비교안을 만들어 넣지 않는다. 선택 이유가 미확인이면 확인된 선택·구현과 확인이 필요한 이유를 구분한다. 구현 결과를 운영 성과로 바꾸거나 없는 지표·원인·효과로 사례를 완성하지 않는다.
- 코드·PR·화면·도식·테스트·측정 등 주장에 맞는 증거를 고르고, 증거가 무엇을 보여 주며 어디까지 확인하는지 바로 옆에 설명한다. 링크 개수로 설명을 대신하지 않는다.

## 정보 구조와 정합성

- 빠르게 훑을 요약에서 대표 경험을 고르고, 목록에서 목적·역할·핵심 변화를 파악한 뒤 상세·근거로 이동할 수 있게 한다. 작은 문서는 이 흐름을 한 문서 안에 담아도 된다. 별도 페이지 수를 강제하지 않는다.
- 프로젝트 수를 고정하지 않는다. 직무와 개인 기여를 잘 보여 주는 소수를 먼저 두고 나머지는 탐색할 수 있는 위치에 둔다.
- 제목·도입부에 대상 사용자·서비스 목적·맡은 작업을 드러낸다. 내부 서비스명·기술명을 먼저 아는 독자를 전제하지 않는다.
- 상세는 이력서 불렛을 길게 풀어 쓴 반복에 머물지 않게 한다. 이력서에서 생략한 제약·판단·실제 변경·검증·한계를 보강하고, 제공된 이력서와 역할·기간·기술·결과를 대조한다. 충돌은 공통 기준으로 처리한다.
- 정합성 점검을 이유로 요청받지 않은 이력서를 수정하지 않는다. 두 문서의 수정까지 요청받았으면 각각의 역할에 맞춰 정합성을 유지한다. 이력서의 2페이지 권장·명사형 불렛·개인 표기·HTML 앵커 선호를 포트폴리오 전체 규칙으로 가져오지 않는다.
- 정보 전달 디자인과 문제 해결 내용은 구분해서 검토한다. 보기 쉬운 배치만으로 기여의 근거를 인정하거나, 좋은 기술 내용만으로 읽기 어려운 구조를 통과시키지 않는다. 점수표는 요청·필요에 맞춰 사용한다.

## 확인과 전달

공통 출력 기준으로 요청 매체의 실제 읽기 흐름·탐색·잘림·링크를 확인하고, 본문·증거·이력서 간 사실 정합성을 점검한다. 작성본 또는 요청 파일을 먼저 제공하고 미확정 정보·실제로 확인한 화면과 조건·남은 검증을 짧게 알린다. 본문 검토만으로 코드·동작·모든 화면 검증을 완료했다고 보고하지 않는다.
