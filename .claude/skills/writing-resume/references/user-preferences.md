# 현재 사용자의 이력서 편집·표기 선호

이 사용자의 **자유양식 이력서**에 적용하는 기본 선호다. 다른 지원자·포트폴리오·일반 글쓰기의 보편 규칙이 아니다. 최신 사용자 지시와 기업 지정 양식을 우선하며, 이후 정정된 선호가 이전 선호보다 우선한다.

## 불렛 본문

- 개조식 항목의 끝 마침표는 생략한다. 서로 다른 문장의 마침표만 지워 붙이지 말고, 독립 기여를 분리하거나 자연스럽게 다시 쓴다. 소개글 같은 서술형 문장에는 일괄 적용하지 않는다.
- 기능·범주를 나열하는 **같은 묶음**이 2~3개면 쉼표, 4개 이상이면 `/`를 쓴다. 예: `접수, 재시도, 작업 복구`, `교육/문화/복지/일자리`. 한 문장 전체의 쉼표 개수로 판단하지 않는다.
- 기호가 필요하지 않으면 `와`, `과`, `및`을 쓴다. 함께 쓰는 기술이나 인과관계를 기계적으로 쉼표·`/`로 바꾸지 않는다.
- 이 기호 기준은 불렛 본문에만 적용한다. 제목·메타 정보·기술 스택·일반 설명은 일괄 변경하지 않으며 본문 밖 구분용 `·`는 허용한다. 기술명·날짜·학점·URL에 포함된 점·슬래시는 보존한다.

## 경력 표기와 배치

- 회사명 아래는 한국어 `직무 · 근무 형태`로 간결하게 적는다. `담당 영역` 라벨이나 별도 역할 설명을 붙이지 않는다. 원격근무가 확인되면 `계약직(원격근무)`처럼 쓸 수 있다. 팀·부서·직급은 만들지 않는다.
- 교환학생은 `해외 경험`으로 분리하고 영어 활용 수준을 함께 배치한다. 영어 하나 때문에 기술 목록에 독립 행을 추가하거나 협업 항목을 억지로 넓히지 않는다. 활용 수준은 확인된 범위만 쓴다.
- 경력·프로젝트 아래 기술 스택은 인라인 코드로 표시하고 CSS 원형 구분자를 추가하지 않는다. 기술 섹션 전체 분류나 기존 태그를 바꾸는 것으로 확대하지 않는다.
- 제안한 분류안을 사용자가 확정하기 전에 기본 규칙으로 저장하지 않는다. 회사별 직무·고용 형태 같은 개인 사실은 원자료에서 확인하며 이 참조에 저장하지 않는다.

## 목차가 있는 HTML 이력서

해당 동작을 새로 만들거나 수정·검토하는 작업에만 적용한다. 새로고침 시 목차 앵커 주소를 초기화하고 직전에 보던 스크롤 위치를 유지한다. 목차 클릭 이동은 정상 작동해야 한다. 문장 수정마다 재구현하거나 일반 문서·포트폴리오 사이트에 적용하지 않는다.
