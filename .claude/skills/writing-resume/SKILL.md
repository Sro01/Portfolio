# writing-resume

지원 직무에 맞춰 담당 역할·사용 기술·결과를 빠르게 읽을 수 있는 한국어 이력서를 작성한다.

## 시작과 참조

1. 먼저 [writing-common](../writing-common/SKILL.md)을 읽고 사실·출처 충돌·본인 기여·STAR 분석·대표 경험 선별 기준을 적용한다. 이번 작업에서 이미 읽었으면 중복 로딩하지 않는다.
2. **마스터**, **기업별 제출본**, **기존 문서 검토·수정** 중 목적을 파악한다. 공고·기업/직무명, 원자료, 자유양식/기업 지정 양식, 파일 형식·분량 제한 중 작성에 필요한 누락 정보만 확인한다. 목표 공고가 없어도 마스터 정리는 진행할 수 있다.
3. 항목을 작성하거나 전체 내용을 검토할 때 [항목별 기준](references/sections.md)을 읽는다. 자유양식 이력서 편집에는 [사용자 편집·표기 선호](references/user-preferences.md)를 읽고, 그 안의 HTML 항목은 해당 동작을 다룰 때만 적용한다.

## 경력·프로젝트 압축

- 회사 아래에 서비스나 주요 작업 단위를 묶어 **서비스 목적 → 본인의 역할·책임 → 구체적 기여** 순으로 이해되게 한다. 서비스명만 쓰지 말고 대상 사용자·목적 또는 맡은 작업을 설명한다. 제목은 `서비스명 + 서비스 설명` 또는 `대상 + 수행한 작업`으로 작성한다.
- 회사 근무기간을 임의로 쪼개 프로젝트 기간을 만들지 않는다. 프로젝트별 기간은 별도 근거가 있을 때만 표시한다.
- 관련 작업의 맥락을 유지한다. 필요하면 실제 작업 단위의 소제목을 쓰되 `설계/개발/개선` 범주에 같은 경험을 흩어 놓거나 모든 불렛에 소제목을 붙이지 않는다. 사용자가 업무 성격별 분류를 요청하면 그 형식을 따른다.
- 경력 불렛은 본인이 설계·구현·개선한 **한 핵심 기여**를 한 문장에 담는다. 독립적인 기여는 나누고, 하나의 해결 방식과 결과는 함께 유지한다. 기능마다 잘라 불렛 수만 늘리지 않는다.
- 공통 STAR 분석에서 확인한 근거를 바탕으로 무엇을 위해 무엇을 바꾸었고 무엇이 달라졌는지 압축한다. 상황·목표는 프로젝트 설명과 반복하지 않고 실제 조치와 확인된 결과를 중심에 둔다.
- 기술명·`통합`·`연동`·`구조 설계`만 나열하지 않는다. 연결한 데이터·분리한 경계·변경한 처리 흐름·사용자가 할 수 있게 된 일을 구체화한다. 기술 용어 풀이나 동일 기여의 표현만 바꾼 반복으로 분량을 채우지 않는다.
- 선택 이유가 설명력을 높이면 `서비스 규모를 고려한 …`처럼 짧게 담는다. 모든 불렛에 문제·이유·대안·수치를 붙이지 않는다. 수치가 없는 경우에도 공통 기준에서 확인한 동작·구조의 변화를 결과로 쓸 수 있다.
- 오류 수정 대표 사례는 공통 선별 기준을 통과한 경우 어떤 문제를 어떻게 해결했는지 적는다. 조사·재현·가설·실험을 시간순으로 나열하지 않고 최종 조치와 결과를 남긴다. 상세한 판단 과정은 포트폴리오·면접 근거로 분리하되, 요청 없이 포트폴리오를 새로 제작하지 않는다.

## 분량·문체·양식

- **마스터:** 활용 가능한 이력을 충분히 보관한다. **제출본:** 직무 관련성이 높은 경험을 먼저 고르고 최대 2페이지를 권장하되 기업 분량 규정을 우선한다. 한 페이지에 과도하게 압축하거나 화면 폭에 맞춰 글자를 줄이고 강제로 한 줄 처리하지 않는다.
- 담당업무·경력·프로젝트 세부 항목은 개조식·명사형으로 통일한다. 짧은 소개글에는 서술식을 허용한다.
- 날짜는 기본 `YYYY.MM`, 일자까지 요구하면 `YYYY.MM.DD`로 통일한다. 알려지지 않은 일자는 만들지 않는다. 같은 목록은 최근순을 기본으로 하며 직무 관련성으로 조정해도 기간은 분명하게 표시한다.
- 자유양식은 이력과 직무에 맞게 항목을 조정한다. 기업 지정 양식의 항목은 임의로 삭제하지 않는다. 빈 행 추가·삭제도 서식과 안내가 허용하는 범위에서만 하며, 해당 없는 항목은 지정 표기를 따른다.
- 글자 수 계산·링크·실제 파일 저장·HTML/PDF 확인은 공통 스킬의 출력 확인 기준을 적용한다. 페이지 수 권장은 포트폴리오의 분량 제한이 아니다.

## 제출 전 확인과 전달

- 공통 사실 검증을 마치고, 지원 기업·직무·연락처와 필수 항목·분량 제한을 확인한다.
- 서비스 내부 용어를 몰라도 목적·역할·실제 변경을 이해할 수 있는지, 직무 관련 경험이 먼저 보이는지 확인한다.
- 독립적인 기여와 반복 서술을 구분하고, 명사형·날짜·사용자 선호·양식 준수 및 요청 매체의 가독성을 확인한다.
- 완성본 또는 저장한 파일을 먼저 제공한 뒤 필요한 미확정 정보와 실제 출력 검증 범위를 짧게 알린다.
