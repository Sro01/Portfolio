# 커밋 메시지 규칙

이 규칙은 이 프로젝트의 커밋에 적용합니다. 개인 포트폴리오를 관리하면서 변경 내용과 이유를 다시 이해할 수 있도록 간결하게 기록합니다.

## 제목

```text
type(scope): 한글 요약
```

- type은 `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `build`, `perf`, `revert` 중에서 변경 목적에 맞게 선택합니다.
- scope는 `web`, `ui`, `i18n`, `content`, `docs`, `config`, `deploy` 등 실제 변경 영역을 나타내는 영문으로 작성합니다. 필요한 영역은 추가할 수 있습니다.
- 요약은 변경 결과를 구체적으로 적고, “표시한다”, “분리한다”, “유지한다”처럼 종결형으로 작성합니다. 끝에 마침표는 붙이지 않습니다.
- 요약은 한글 40자 안쪽을 목표로 한 줄로 작성합니다. 긴 근거와 세부 조건은 본문으로 옮깁니다.
- “버그 수정”, “오류 처리 개선”처럼 결과를 알 수 없는 표현은 사용하지 않습니다.
- 호환성을 깨는 변경은 `type(scope)!:`로 표시합니다. 필요한 경우 본문 뒤에 별도의 `BREAKING CHANGE:` footer로 영향과 필요한 조치를 설명합니다. 계약 변경을 `refactor`로 숨기지 않습니다.

## 본문

- 제목과 본문 사이에는 빈 줄을 둡니다.
- 본문은 `-`로 시작하는 불릿포인트로 작성합니다. 각 불릿은 하나의 내용을 설명합니다.
- 무엇을 어떤 방식으로 바꿨는지와 그 이유를 간결하게 기록합니다. 서로 연결된 내용은 한 불릿으로 합쳐도 됩니다.
- 제목을 그대로 반복하거나 코드의 변경 사항을 줄별로 나열하지 않습니다.
- 변경 설명은 “추가한다”, “분리한다” 같은 종결형으로 작성합니다. 검증 결과는 “확인”, “통과”, “실패”처럼 간결하게 적어도 됩니다.
- 오타·서식 등 자명한 변경은 제목만 작성할 수 있습니다. 그 외에는 본문을 작성합니다.

### 검증과 미검증 사항

- 동작 변경에는 `- 검증:`으로 실제 확인한 내용과 결과를 기록합니다. 명령을 실행했다면 명령과 통과·실패 결과를 함께 적습니다.
- 검증을 전혀 수행하지 못했다면 `- 미검증:`으로 대상과 이유를 적습니다. 일부만 검증했다면 검증한 범위와 남은 미검증 대상을 구분합니다.
- “테스트 완료”, “돌렸다”, “추가 테스트 필요”처럼 확인 범위나 결과를 알 수 없는 문구로 끝내지 않습니다.
- 실행하지 않은 테스트, 확인하지 않은 결과, 측정하지 않은 수치를 만들어 적지 않습니다.
- 문서 등 비동작 변경도 검증 내용을 남길 필요가 있으면 같은 형식을 사용할 수 있습니다.

### 필요할 때만 적는 내용

- 중요한 제약과 그 근거, 실제 검토하고 버린 대안과 이유, 남은 문제, 배포 시 필요한 조치를 관련 불릿에 설명합니다.
- 대안이나 위험을 채우기 위해 내용을 꾸미지 않습니다. 추론은 확인된 사실과 구분합니다.
- `Confidence`, `Scope-risk`, `Constraint`, `Rejected` 같은 고정 메타데이터 필드는 요구하지 않습니다.
- 동작이나 계약 변경으로 기존 명세가 달라지면 관련 문서도 함께 갱신합니다.

## 예시

다음은 형식 예시입니다. 검증 문장은 실제로 확인한 경우에만 사용합니다.

```text
feat(web): 프로젝트 목록을 언어별 콘텐츠로 표시한다

- 프로젝트 데이터를 언어별로 나눠 접속한 언어의 제목과 요약을 보여 준다
- 목록 카드는 shadcn Card를 조합해 만들고 화면 문구는 messages/에서 불러온다
- 검증: pnpm check 통과, /ko·/en·/ja·/de에서 목록이 각 언어로 표시됨을 확인
- 미검증: 모바일 화면 폭의 레이아웃은 확인하지 못해 미확인
```

```text
docs(config): 프로젝트 공통 커밋 규칙을 정의한다

- 변경 방식과 이유를 쉽게 확인할 수 있도록 본문을 불릿포인트로 통일한다
- 에이전트마다 같은 규칙을 참고하도록 AGENTS.md와 CLAUDE.md에 참조를 추가한다
```

```text
docs(web): 프로젝트 소개의 오타를 수정한다
```
